# Design: TTS, Subtitle Alignment, and Job Validation

## TTS Provider Enhancement

### synthesize_with_timing contract

```python
class TTSProvider(ABC):
    @abstractmethod
    def synthesize(self, text: str, output_path: str, options: TTSOptions) -> TTSResult:
        ...

    def synthesize_with_timing(self, text: str, output_path: str,
                                options: TTSOptions) -> TTSResult:
        """Default: calls synthesize() + _measure_audio(), no timing data.
        Override in providers that support word/sentence boundaries."""
```

### EdgeTTSProvider.synthesize_with_timing

Streams from edge_tts capturing WordBoundary and SentenceBoundary events, returns TTSResult with `timing_data` containing both.

### Voice configuration

- `TTS_PROVIDER` (default: `edge_tts`)

## Subtitle Provider modes

| Mode | Source | Confidence | Fallback |
|------|--------|-----------|----------|
| `estimated` | Uniform word distribution | low | None |
| `whisper` | faster-whisper transcription | high | → estimated |

### Whisper word grouping rules

- Target: 2-7 words per cue
- Max 2 lines (handled by ASS wrapping)
- Split on sentence endings (`.!?`), pauses (>0.4s), length (≥6 words)
- Avoid single-word cues unless justified by emphasis/pause
- Avoid overlaps (sequential non-overlapping time ranges)

## Validation Script

`bin/validate_job.py <metadata_path>` checks:
1. Asset files exist per scene (images/segments)
2. Audio files exist per scene
3. No zero-size files
4. Durations valid (>0)
5. ASS subtitle file exists
6. No overlapping cues
7. Cues cover audio reasonably
8. Manifest exists and paths are valid
9. If video.mp4 exists, verify resolution 1080x1920 via ffprobe
10. Non-zero exit code on blocking errors
11. Human-readable report + JSON output

## Edge TTS Native Timing (Jul 3 2026)

### Subtitle Timing Provider

`--subtitle-timing-provider` CLI flag with modes:

| Mode | Behavior |
|------|----------|
| `auto` | Prefer edge_tts WordBoundary → fallback whisper → estimated |
| `edge_tts` | Force Edge TTS WordBoundary as primary timing source |
| `whisper` | Force Whisper reconciliation |
| `estimated` | Uniform word distribution |

The env var `SUBTITLE_TIMING_PROVIDER` sets the default. Falls back to `SUBTITLE_PROVIDER` for backward compatibility.

### Edge TTS library patch

The `edge_tts` v7.2.8 library sends `speech.config` with mutually exclusive `wordBoundaryEnabled`/`sentenceBoundaryEnabled` (only one true at a time). Default is `SentenceBoundary`. Patched at `communicate.py` line 426-440 to always set both to `"true"`.

### Punctuation Annotation for WordBoundary Text

Edge TTS strips punctuation from WordBoundary text (e.g., "1453," → "1453", "milenario." → "milenario"). This defeats the `is_end_of_sentence` and `is_medium_with_punct` heuristics in `group_words_into_cues()`.

**Fix**: `_annotate_word_punctuation(words, full_text)` cross-references each WordBoundary word with the canonical narration text (which has punctuation). For each WordBoundary word, it finds the matching canonical word (by stripping punctuation from canonical) and recovers trailing punctuation characters.

```python
def _annotate_word_punctuation(words, full_text):
    canon = full_text.split()
    for w in words:
        wt = w["text"].strip()
        for ci, cw in enumerate(canon[ci:], ci):
            cs = cw.strip(".,!?;:¡¿()\"'-")
            if wt.lower() == cs.lower():
                punct = "".join(ch for ch in cw[len(cs):] if ch in ".,!?;:")
                annotated.append({**w, "text": wt + punct})
                break
```

This allows the existing heuristics to detect punctuation: `is_medium_with_punct` splits after commas (`"1453,"`), `is_end_of_sentence` splits after sentence-ending punctuation (`"milenario."`).

### Sentence Boundary Handling

Changed from active flush to silent consumption:

- **Before**: Sentence boundary check flushed the buffer (any non-empty), then popped consumed boundaries. This created short cues at the start of new sentences that would merge backward if <0.7s.
- **After**: Sentence boundaries are ONLY consumed (popped) when a word is past the split point. Cue breaks are driven entirely by the annotation-based heuristics (`is_end_of_sentence`, `is_medium_with_punct`, `is_long_enough`, `is_pause`). Short cues at sentence boundaries are prevented from merging backward via the `sb_breaks` check in post-processing.

### Merge Prevention

The <0.7s short-cue merge in post-processing checks `sb_breaks` (a copy of `sb_end_times`): if a short cue's `startSec` is within 0.1s of any sentence boundary break, it is NOT merged backward. This prevents single-word cues at the start of a new sentence from leaking into the previous sentence's last cue.

### Sentence Boundary Splitting

**Problem**: `group_words_into_cues()` used `(sb["offset"] + sb["duration"]) / TICK` (sentence end time) as split point between sentences. However, WordBoundary events for the first word of the next sentence can start BEFORE this end time. Debug data showed:

- Sentence 1 end (offset + duration): **6.138s**
- Sentence 2 start (offset only): **6.088s**  
- First word of sentence 2 ("La"): **6.112s**

With old code: `6.112 >= 6.138` → False → "La" absorbed into previous cue → sentence boundary crossed.

**Fix**: Use the **next sentence's `offset`** as the split point instead of the current sentence's `offset + duration`:

```python
for i, sb in enumerate(sentence_boundaries):
    if i < len(sentence_boundaries) - 1:
        end_sec = sentence_boundaries[i + 1]["offset"] / 10_000_000
    else:
        end_sec = (sb["offset"] + sb["duration"]) / 10_000_000
    sb_end_times.append(round(end_sec, 3))
```

**Rationale**: SentenceBoundary `offset` represents where each sentence's audio BEGINS in the stream. Using the next sentence's start as the current sentence's split point ensures that the first word of the next sentence always triggers a flush, even when the previous sentence's `offset + duration` overestimates its end by ~50ms.

### SUBTITLE_GLOBAL_OFFSET_MS

Applied after cue generation, before writing to metadata. Shifts all `startSec`/`endSec` by `offset_ms / 1000.0`. Default 0. Intended for A/B calibration, not as a permanent fix.

## Default Timing Mode Decision (Jul 3 2026)

### Decision: Edge TTS Native Timing is the default

After rendering and comparing both timing modes side by side:

| Criterion | Edge | Whisper |
|-----------|------|---------|
| Coverage | **78%** (23.9s / 30.9s) | 69% (21.3s / 30.9s) |
| Validation | PASS, 0 errors | PASS, 0 errors |
| Scene 1 inter-cue gap | **0.21s** | 0.90s |
| Timing source | **Native TTS word boundaries** | Whisper ASR (reconciled) |
| Leading punctuation (¡/¿) | Missing (cosmetic) | Preserved |

**Rationale**: Edge mode provides higher subtitle coverage, tighter timing synchronization (native from TTS engine), and smaller gaps between cues. The known leading-punctuation loss (¡/¿) is cosmetic and non-blocking. The sentence boundary splitting and punctuation annotation infrastructure was purpose-built for this mode.

**Effective immediately**: `--subtitle-timing-provider` defaults to `edge_tts` in `auto` mode (prefer edge, fallback whisper, then estimated).

### Regression Tests

`tests/test_timing_regression.py` covers four edge cases:
1. **sentence_boundary_crossing** — no words leak across sentence boundaries within same scene
2. **punctuation_restoration** — trailing commas/periods recovered from canonical text
3. **no_cross_scene_leakage** — cues respect scene window boundaries
4. **no_single_word_by_boundary** — no single-word cue created solely by boundary handling

These are non-blocking fixtures meant to prevent regressions during future changes to grouping logic.

## Decisions (Jul 2 2026)

### Path format in manifest
All paths in `job-manifest.json` are relative to `project_root`. `_resolve_relative()` in `render_job.py` converts any absolute path in asset segments to relative. This ensures portability across environments.

### ffprobe resolution strategy in validate_job.py
`validate_job.py` uses a three-tier strategy:
1. **Local ffprobe** — `shutil.which("ffprobe")`, calls directly with `subprocess.run`
2. **Docker ffprobe** — `linuxserver/ffmpeg:latest` via `docker run --rm`
3. **Unavailable** — returns `None`, caller emits WARNING and skips the check

This eliminates the hard Docker dependency while preserving Docker usage when available.

### `--skip-render` flag (render_job.py)

Added `--skip-render` to `render_job.py` to enable manifest generation without Docker or FFmpeg. When set:
- FFmpeg render is skipped entirely
- Post-render validation (duration, black frames, freeze frames) uses dummy safe defaults
- Audio validation and coverage validation are skipped
- Job manifest is still generated with all required fields
- Final JSON summary uses `actualVideoDurationSec: 0` and `durationDeltaSec: 0`

This allows validation of asset paths, subtitle cues, and manifest structure in CI/testing without a full rendering environment.
